# 服务器 `backend/.env` 配置说明

本文用于腾讯云 Ubuntu + Docker Compose 部署。本文件应保存为：

```text
/opt/ai-resume-screening/backend/.env
```

`.env` 含数据库密码、模型密钥，**不得提交 GitHub、不得上传到公开网盘、不得发送到聊天中**。

## 1. 完整配置模板

复制下面内容到服务器的 `backend/.env`，将尖括号中的值替换为真实值。

```env
# ---------- 应用 ----------
APP_ENV=production
APP_NAME=AI Resume Screening
# 使用下方命令生成，不要使用示例值。
APP_SECRET=<至少32位随机字符串>
API_PREFIX=/api/v1

# 没有域名时使用公网 IP；有 HTTPS 域名后替换为 https://你的域名。
CORS_ORIGINS=["http://49.232.199.64"]

# ---------- 腾讯云 MySQL ----------
MYSQL_HOST=<腾讯云MySQL内网地址或公网地址>
MYSQL_PORT=3306
MYSQL_DATABASE=<数据库名称>
MYSQL_USERNAME=<数据库账号>
MYSQL_PASSWORD=<数据库密码>
# 腾讯云 MySQL 启用 SSL 时写 true；未启用时写 false。
MYSQL_SSL=true
# 不需要 CA 证书时留空；强制 CA 验证时填写容器内可访问的绝对路径。
MYSQL_SSL_CA=

# ---------- 模型服务（OpenAI 兼容接口） ----------
LLM_PROVIDER=openai-compatible
# 只填写 API 基础路径，不要填写 /chat/completions。
# 当前 tong.becca.top 网关必须保留 /v1。
LLM_BASE_URL=http://tong.becca.top:8081/v1
LLM_API_KEY=<模型API密钥>
LLM_MODEL=gpt-5.5
# 当前网关已验证可使用 1。
LLM_TEMPERATURE=1

# ---------- JD 与简历分析 ----------
JD_LLM_MAX_TOKENS=1200
JD_LLM_TIMEOUT_SECONDS=55
RESUME_LLM_ENABLED=true
# 限制单份简历模型输入与输出，避免第三方模型网关拒绝大请求。
RESUME_LLM_MAX_INPUT_CHARS=24000
RESUME_LLM_MAX_TOKENS=1600

# ---------- 扫描版 PDF / 图片型 PDF ----------
# 只有模型确认支持 image_url 图片输入时才设为 true。
# gpt-5.5 是否支持视觉能力取决于你的网关套餐；不确定时先设为 false。
RESUME_VISION_ENABLED=false
RESUME_VISION_MODEL=
RESUME_VISION_MAX_PAGES=5
RESUME_VISION_DPI=160

# Docker Compose 会覆盖为 /data/storage；不要改为 Mac 路径。
LOCAL_STORAGE_PATH=/data/storage

# ---------- Worker 任务 ----------
TASK_MAX_ATTEMPTS=3
TASK_LEASE_SECONDS=300
TASK_HEARTBEAT_SECONDS=30
TASK_RETRY_BASE_SECONDS=15
TASK_RETRY_MAX_SECONDS=300
# 4 核 4GB 服务器 + 第三方模型网关建议保持 2。
WORKER_CONCURRENCY=2
```

## 2. 首次创建与权限设置

```bash
cd /opt/ai-resume-screening
sudo nano backend/.env
sudo chown root:root backend/.env
sudo chmod 600 backend/.env
```

生成 `APP_SECRET`：

```bash
openssl rand -hex 32
```

在 Nano 中保存：`Ctrl + O` → 回车 → `Ctrl + X`。

## 3. 修改配置后生效

修改 `.env` 后，不能只执行 `docker compose restart`，因为它不会重新创建容器读取环境变量。执行：

```bash
cd /opt/ai-resume-screening
sudo docker compose up -d --force-recreate api worker
sudo docker compose ps
```

若本次同时更新了源码（例如新增 `WORKER_CONCURRENCY` 功能），先构建再启动：

```bash
cd /opt/ai-resume-screening
sudo docker compose build api worker
sudo docker compose up -d --force-recreate api worker
```

## 4. 配置验证

以下命令不显示 API Key，可确认容器读取到的模型基础地址：

```bash
cd /opt/ai-resume-screening
sudo docker compose exec api python -c 'from app.core.config import get_settings; print(get_settings().effective_llm_base_url)'
```

当前网关应输出：

```text
http://tong.becca.top:8081/v1
```

确认 Worker 已使用新并发数：

```bash
sudo docker compose logs --tail=30 worker
```

最新代码应出现：

```text
Resume worker started: ... (concurrency=2)
```

## 5. 常见错误

| 现象 | 原因与处理 |
| --- | --- |
| `404 ... /v1/chat/completions` | 先执行第 4 节验证；当前 `tong.becca.top` 的正确基础地址是 `http://tong.becca.top:8081/v1`。 |
| `Expecting value: line 1 column 1` | 多数情况下模型地址错误地去掉了 `/v1`，请求命中了网页 HTML；恢复第 1 节的 `LLM_BASE_URL`。 |
| `invalid temperature: only 1 is allowed` | 设置 `LLM_TEMPERATURE=1`，随后使用第 3 节命令重建 `api` 与 `worker`。 |
| Worker 显示 `concurrency=8` | 服务器源码还是旧版本；更新源码、执行 `docker compose build api worker`，再重建容器。 |
| 扫描 PDF 解析失败 | 若没有配置已验证的视觉模型，保持 `RESUME_VISION_ENABLED=false`；需要 OCR 时配置支持图片输入的模型后再开启。 |
