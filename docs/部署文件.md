# AI 招聘简历筛选系统部署指南

> 适用当前工程：Vue 3 静态前端 + FastAPI API + 独立 Python Worker + MySQL 8。本指南面向**腾讯云 CVM 全新 Ubuntu 24.04 LTS**，采用单台 Linux 服务器、Nginx 反向代理和 systemd 部署。当前工程没有 Dockerfile 或 Docker Compose；不要混用 Docker、Vite 开发服务器和 systemd。

> 4 核 4GB / 48GB 磁盘可用于小团队、低并发场景：MySQL 和大模型必须使用云服务或外部 API，不在此服务器本地运行；API 仅使用 1 个 worker，并为系统配置 2GB Swap。

## 1. 部署拓扑

```text
浏览器
  │ HTTPS :443
Nginx
  ├─ /              → Vue 构建产物（静态文件）
  └─ /api/          → FastAPI（127.0.0.1:8000）
                         │
                      MySQL 8（远程或本机）
                         │
                    Python Worker（轮询 processing_tasks）
                         │
                 本机持久化目录（PDF / 预解析文本）
```

API 和 Worker 必须同时运行。API 仅创建、查询任务；Worker 不运行时，简历会一直停留在等待解析或等待分析状态。

## 2. 推荐方式：腾讯云 OrcaTerm + ZIP + Docker（从这里开始）

如果你通过 GitHub 下载 ZIP、再用腾讯云 OrcaTerm 上传到服务器，请只按本节操作。**不需要** `git clone`、`resumeapp`、Python 虚拟环境、Node.js 或 systemd；这些是后文面向熟悉 Linux 命令的备用方案。

### 2.1 腾讯云控制台准备

1. 创建 Ubuntu 24.04 LTS CVM（4 核 4GB / 48GB 可用）。
2. 在安全组中只放行 TCP `22`、`80`、`443`；不要开放 `8000`、`3306`、`8080`。
3. 将域名 A 记录指向服务器公网 IP。没有域名时可以先使用 `http://公网IP` 验证，完成后再配置 HTTPS。
4. 在本地 GitHub 页面下载 `rimetli/jdfiter` 的 `main` 分支 ZIP，不要上传本地 `node_modules`、`.venv`、`dist` 或任何简历文件。

### 2.2 使用 OrcaTerm 上传两个文件

在 OrcaTerm 的文件上传面板上传到服务器 `/home/ubuntu/`：

- `jdfiter-main.zip`（GitHub 下载的源码压缩包）
- `ai-resume-screening.env`（本地 `backend/.env` 改名后的副本）

不要上传 `.env.example` 代替真实 `.env`；也不要把密码、模型密钥写进 ZIP。上传后，在 OrcaTerm 终端执行：

```bash
cd /home/ubuntu
ls -lh jdfiter-main.zip ai-resume-screening.env
```

两个文件均显示出来后再继续。若 GitHub ZIP 的名称不同，把下面命令中的 `jdfiter-main.zip` 替换成实际文件名。

### 2.3 一次性解压、安装 Docker 并启动

以下命令可整段复制到 OrcaTerm 终端。它会安装 Nginx、解压 ZIP、安装 Docker、放置配置文件并创建简历存储目录；完成后先检查第 2.4 节的配置，再构建和启动：

```bash
sudo apt update && sudo apt install -y unzip nginx

sudo mkdir -p /tmp/ai-resume-release /opt/ai-resume-screening
sudo unzip -q /home/ubuntu/jdfiter-main.zip -d /tmp/ai-resume-release
sudo cp -a /tmp/ai-resume-release/jdfiter-main/. /opt/ai-resume-screening/

sudo install -o root -g root -m 600 \
  /home/ubuntu/ai-resume-screening.env \
  /opt/ai-resume-screening/backend/.env

cd /opt/ai-resume-screening
sudo bash deploy/scripts/install-docker-ubuntu.sh

sudo mkdir -p /srv/data/ai-resume-screening/storage
sudo chown -R 10001:10001 /srv/data/ai-resume-screening
sudo chmod 750 /srv/data/ai-resume-screening /srv/data/ai-resume-screening/storage
```

如果命令在 `cp -a ... jdfiter-main` 处报“目录不存在”，先执行：

```bash
ls -l /tmp/ai-resume-release
```

将命令中的 `jdfiter-main` 改为列表中实际的目录名后，从 `sudo cp -a` 那行继续执行。不要重新上传 ZIP，也不要执行删除数据库的命令。

### 2.4 先检查并修改服务器配置

在首次启动前编辑服务器上的配置文件：

```bash
sudo nano /opt/ai-resume-screening/backend/.env
```

必须确认以下字段是真实的腾讯云/模型配置；Docker 会自动设置 `LOCAL_STORAGE_PATH`，不需要手工修改它：

```dotenv
APP_ENV=production
APP_SECRET=至少32位随机字符串
CORS_ORIGINS=["https://你的域名"]

MYSQL_HOST=腾讯云MySQL地址
MYSQL_PORT=3306
MYSQL_DATABASE=resume_screening
MYSQL_USERNAME=数据库账号
MYSQL_PASSWORD=数据库密码
MYSQL_SSL=true

LLM_PROVIDER=openai-compatible
LLM_BASE_URL=模型接口地址
LLM_API_KEY=模型密钥
LLM_MODEL=文本模型名称
RESUME_LLM_ENABLED=true
```

没有域名时可以临时写 `CORS_ORIGINS=["http://服务器公网IP"]`，申请 HTTPS 后改回实际域名。保存后执行以下命令构建、建表并启动：

```bash
cd /opt/ai-resume-screening
sudo docker compose build
sudo docker compose run --rm api python -m alembic upgrade head
sudo docker compose up -d
sudo docker compose ps
curl -fsS http://127.0.0.1:8080/api/v1/health
curl -fsS http://127.0.0.1:8080/api/v1/health/database
```

### 2.5 配置域名、Nginx 与 HTTPS

将模板复制到宿主机 Nginx，修改其中的 `recruit.example.com` 为实际域名后启用：

```bash
sudo cp /opt/ai-resume-screening/deploy/nginx/ai-resume-screening-docker.conf \
  /etc/nginx/sites-available/ai-resume-screening
sudo nano /etc/nginx/sites-available/ai-resume-screening
sudo ln -s /etc/nginx/sites-available/ai-resume-screening /etc/nginx/sites-enabled/ai-resume-screening
test -L /etc/nginx/sites-enabled/default && sudo unlink /etc/nginx/sites-enabled/default || true
sudo nginx -t && sudo systemctl reload nginx

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d recruit.example.com
```

访问 `https://你的域名`，首次先通过接口初始化组织：

```bash
curl -X POST https://你的域名/api/v1/setup/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"organization_name":"你的公司或团队"}'
```

随后打开 `https://你的域名/login` 创建管理员账号。查看问题时只需使用：

```bash
cd /opt/ai-resume-screening
sudo docker compose ps
sudo docker compose logs -f api
sudo docker compose logs -f worker
```

> Docker 的端口只绑定到 `127.0.0.1:8080`；宿主机 Nginx 是唯一的公网入口。不要为了“方便”把 Compose 改为 `8080:80`。

## 3. 补充：上线前确认

- 已准备域名并将 A/AAAA 记录指向服务器公网 IP；建议使用 `recruit.example.com`，不要与后续应用共用路径前缀。
- 腾讯云安全组仅放行 TCP `22`（限制为管理员固定 IP）、`80`、`443`；**不要**放行 `8000` 或 `3306` 到公网。
- MySQL 8 已创建数据库和最小权限账号，服务器网络可访问该数据库。
- 腾讯云 MySQL 白名单已加入本 CVM 的出口公网 IP（或同一 VPC 的私网网段），并按实例要求启用 SSL。
- 已准备兼容 OpenAI Chat Completions 的模型地址、API Key 和模型名。
- 若需扫描版 PDF OCR，所选模型必须支持图片 `image_url` 输入。
- 服务器磁盘有足够空间保存简历；当前文件存储是本地目录，不能部署为无持久化的临时容器磁盘。
- 候选人、简历、任务、评估与能力模型接口已按账户和岗位归属鉴权；仍须完成 [安全与权限文档](05-安全合规与权限.md) 中的文件安全、个人信息加密、审计与初始化入口收紧后再开放公网。

## 4. 全新服务器初始化与系统依赖

以腾讯云提供的 `ubuntu` 管理账号连接服务器。以下命令全部在出现 `ubuntu@...$` 提示符时执行：

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y git nginx curl ca-certificates gnupg ufw python3 python3-venv python3-pip

# 安装 Node.js 22 LTS；不要使用 Ubuntu 仓库中可能过旧的 Node.js。
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

检查版本：

```bash
python3 --version
node --version
npm --version
nginx -v
```

项目要求 Python `3.11+` 和 Node.js `22+`。若 Python 低于 3.11，停止后续步骤并改用 Ubuntu 24.04 镜像或先安装满足版本要求的 Python；不要用 Python 3.10 创建虚拟环境。

4GB 内存机器建议创建 2GB Swap（全新机器只执行一次）：

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048 status=progress
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
swapon --show
free -h
```

启用服务器本机防火墙前，务必先放行 SSH；防火墙规则与腾讯云安全组需要同时配置：

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose
```

## 5. 创建运行账号与目录

以下示例将工程部署到 `/opt/ai-resume-screening`，用专用低权限账号运行。`/var/lib` 属于系统目录，必须先由具有 `sudo` 权限的管理员创建，再授权给运行账号；不要使用 `sudo -u resumeapp` 直接在 `/var/lib` 下创建顶层目录。

```bash
# 1. 创建不可登录的应用运行账号；账号已存在时可跳过本行。
sudo useradd --system --create-home --shell /usr/sbin/nologin resumeapp

# 2. 创建代码目录，并将其交给应用账号。
sudo mkdir -p /opt/ai-resume-screening
sudo chown resumeapp:resumeapp /opt/ai-resume-screening

# 3. 创建持久化数据目录。此处必须使用 sudo，不能切换为 resumeapp 执行。
sudo mkdir -p /var/lib/ai-resume-screening/storage
sudo chown -R resumeapp:resumeapp /var/lib/ai-resume-screening
sudo chmod 750 /var/lib/ai-resume-screening
sudo chmod 750 /var/lib/ai-resume-screening/storage

# 4. 以低权限账号拉取代码。
sudo -u resumeapp git clone https://github.com/rimetli/jdfiter.git /opt/ai-resume-screening
sudo -u resumeapp git -C /opt/ai-resume-screening status
```

验证应用账号拥有数据目录读写权限：

```bash
sudo -u resumeapp touch /var/lib/ai-resume-screening/storage/.write-test
sudo -u resumeapp rm /var/lib/ai-resume-screening/storage/.write-test
sudo -u resumeapp test -w /opt/ai-resume-screening && echo "代码目录可写"
```

若第一条 `touch` 报 `Permission denied`，重新执行上面的 `chown` 与 `chmod`；不要把目录设置为 `777`。若代码通过压缩包上传，解压后仍需保证 `/opt/ai-resume-screening` 归 `resumeapp` 所有。不要把 `.env`、真实简历或数据库备份提交到 Git。

复制模板并限制文件权限：

编辑 `backend/.env`，至少设置如下项目（示例值必须替换）：

LLM_BASE_URL=<模型兼容接口地址，例如 https://.../v1>

TASK_MAX_ATTEMPTS=3
TASK_LEASE_SECONDS=300
TASK_HEARTBEAT_SECONDS=30
TASK_RETRY_BASE_SECONDS=15
TASK_RETRY_MAX_SECONDS=300

生成 `APP_SECRET` 的一种方式：

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

不要在终端历史、截图、工单或日志中暴露 `MYSQL_PASSWORD`、`LLM_API_KEY`、`APP_SECRET`。

在迁移前可只验证配置是否能被加载（不会打印任何密钥）：

```bash
sudo -u resumeapp -H bash -c 'cd /opt/ai-resume-screening/backend && .venv/bin/python -c "from app.core.config import get_settings; get_settings(); print(\"配置加载成功\")"'
```

## 9. 方式 A：systemd 部署

选择本方式时，继续本节和下一节的 Nginx 配置；不要同时启动 Docker Compose。

创建 API 服务 `/etc/systemd/system/ai-resume-api.service`：

```ini
[Unit]
Description=AI Resume Screening API
After=network.target

[Service]
User=resumeapp
Group=resumeapp
WorkingDirectory=/opt/ai-resume-screening/backend
Environment=PYTHONUNBUFFERED=1
# 4GB 内存服务器仅使用 1 个 API worker。
ExecStart=/opt/ai-resume-screening/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

创建 Worker 服务 `/etc/systemd/system/ai-resume-worker.service`：

```ini
[Unit]
Description=AI Resume Screening Worker
After=network.target ai-resume-api.service

[Service]
User=resumeapp
Group=resumeapp
WorkingDirectory=/opt/ai-resume-screening/backend
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/ai-resume-screening/backend/.venv/bin/python -m app.worker
Restart=always
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ai-resume-api ai-resume-worker
sudo systemctl status ai-resume-api ai-resume-worker --no-pager
curl -fsS http://127.0.0.1:8000/api/v1/health
curl -fsS http://127.0.0.1:8000/api/v1/health/database
```

查看实时日志：

```bash
sudo journalctl -u ai-resume-api -f
sudo journalctl -u ai-resume-worker -f
```

## 10. 方式 B：Docker Compose 部署（高级说明）

本仓库已提供 `Dockerfile`、`docker-compose.yml`、容器内 Nginx 配置和宿主机 Nginx 反向代理模板。Docker 方式替代上一节的 `ai-resume-api.service` 与 `ai-resume-worker.service`，但仍保留宿主机 Nginx 负责公网 HTTPS。

> 二选一：已选择 Docker 时，不要创建或启用 systemd 的 API/Worker 服务；Docker Compose 已设置 API 1 个 worker、API 900MB、Worker 1500MB 的内存上限，适配 4GB 服务器。

### 9.1 安装 Docker Engine 与 Compose 插件

以下命令使用 Docker 官方 APT 仓库。在 `ubuntu@...$` 下执行：

```bash
sudo apt remove -y docker.io docker-compose docker-compose-v2 docker-doc podman-docker containerd runc || true
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo docker run --rm hello-world
sudo docker compose version
```

Docker 发布端口时可能绕过 UFW 规则；本项目 Compose 文件只将 Web 容器绑定到 `127.0.0.1:8080`，不要改为 `0.0.0.0:8080` 或 `8080:80`。

### 9.2 准备 Docker 持久化目录和配置

Docker 容器内应用使用固定 UID `10001`，需先创建对应的数据目录。`backend/.env` 与 systemd 方式相同，但 Docker 会自动把 `LOCAL_STORAGE_PATH` 覆盖为容器内的 `/data/storage`。

```bash
sudo mkdir -p /srv/data/ai-resume-screening/storage
sudo chown -R 10001:10001 /srv/data/ai-resume-screening
sudo chmod 750 /srv/data/ai-resume-screening /srv/data/ai-resume-screening/storage

cd /opt/ai-resume-screening
test -f backend/.env && echo "后端配置文件已就绪"
```

如尚未配置 `.env`，回到第 7 节完成 MySQL、模型 API 和 `APP_SECRET` 配置；不要把 `.env` 提交到 Git。

### 9.3 构建、迁移并启动容器

```bash
cd /opt/ai-resume-screening
sudo docker compose build
sudo docker compose run --rm api python -m alembic upgrade head
sudo docker compose up -d
sudo docker compose ps

curl -fsS http://127.0.0.1:8080/api/v1/health
curl -fsS http://127.0.0.1:8080/api/v1/health/database
```

查看日志与更新命令：

```bash
sudo docker compose logs -f api
sudo docker compose logs -f worker

# 更新发布：先备份数据库，再拉取、构建、迁移、滚动重建容器。
sudo -u resumeapp git -C /opt/ai-resume-screening pull --ff-only
sudo docker compose build
sudo docker compose run --rm api python -m alembic upgrade head
sudo docker compose up -d --remove-orphans
```

### 9.4 Docker 方式的宿主机 Nginx 与 HTTPS

复制 Docker 专用反向代理模板，并将域名替换为你的实际域名：

```bash
sudo cp /opt/ai-resume-screening/deploy/nginx/ai-resume-screening-docker.conf \
  /etc/nginx/sites-available/ai-resume-screening
sudo nano /etc/nginx/sites-available/ai-resume-screening
sudo ln -s /etc/nginx/sites-available/ai-resume-screening /etc/nginx/sites-enabled/ai-resume-screening
test -L /etc/nginx/sites-enabled/default && sudo unlink /etc/nginx/sites-enabled/default || true
sudo nginx -t
sudo systemctl reload nginx

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d recruit.example.com
```

将配置中的 `recruit.example.com` 换成实际域名，并将 `backend/.env` 中的 `CORS_ORIGINS` 设置为同一个 HTTPS 域名。最后验证：

```bash
curl -fsS https://recruit.example.com/api/v1/health
sudo docker compose ps
```

## 11. 配置 Nginx（仅 systemd 方式）

若已选择第 2 节的 OrcaTerm Docker 快速部署，请跳过本节；其 Nginx 配置已在第 2.5 节完成。

创建 `/etc/nginx/sites-available/ai-resume-screening`：

```nginx
server {
    listen 80;
    server_name recruit.example.com;

    root /opt/ai-resume-screening/frontend/dist;
    index index.html;

    client_max_body_size 25m;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用配置并检查：

```bash
sudo ln -s /etc/nginx/sites-available/ai-resume-screening /etc/nginx/sites-enabled/ai-resume-screening
# 仅当该文件仍是 Ubuntu 默认站点时才移除，避免占用 80 端口。
test -L /etc/nginx/sites-enabled/default && sudo unlink /etc/nginx/sites-enabled/default || true
sudo nginx -t
sudo systemctl reload nginx
```

配置证书（示例使用 Certbot）：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d recruit.example.com
```

完成证书配置后，将 `.env` 的 `CORS_ORIGINS` 保持为实际 HTTPS 域名。若仅通过同域 Nginx 访问，浏览器请求会走 `/api/v1`，无需在前端设置 `VITE_API_BASE_URL`。

## 12. 首次初始化与验证

确认 API 服务正常：

```bash
curl -fsS http://127.0.0.1:8000/api/v1/health
curl -fsS http://127.0.0.1:8000/api/v1/health/database
```

空数据库第一次部署时，先创建组织：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/setup/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"organization_name":"你的公司或团队"}'
```

随后访问 `https://recruit.example.com/login` 创建管理员账号并登录。管理员可在“账户管理”中创建普通账户。

最终验证清单：

1. 能登录，管理员能创建普通账户。
2. 能创建岗位并完成 JD 分析、发布能力模型。
3. 文本 PDF 能解析；扫描 PDF 在视觉模型启用时能 OCR。
4. Worker 日志显示 `PARSE_RESUME`、`ANALYZE_APPLICATION` 任务完成。
5. 批量分析可生成评分、证据和人工结论。
6. 删除测试岗位不会删除其他岗位仍在使用的候选人数据。
7. `sudo systemctl is-enabled ai-resume-api ai-resume-worker` 均显示 `enabled`；重启 CVM 后服务能自动恢复。

## 13. 更新发布流程（仅 systemd 方式）

建议先在测试环境验证，再更新生产。每次更新：

```bash
sudo -u resumeapp -H bash
cd /opt/ai-resume-screening
git pull
cd backend
source .venv/bin/activate
pip install -e '.[dev]'
python -m alembic upgrade head
cd ../frontend
npm ci
npm run build
exit

sudo systemctl restart ai-resume-api ai-resume-worker

```

更新后检查服务状态、健康检查和 Worker 日志。数据库迁移前必须先备份；若迁移不可逆，应先在同版本的备份库演练回滚。

## 14. 日常运维与排错

| 现象 | 检查顺序 |
|---|---|
| 页面 502 | `systemctl status ai-resume-api` → API 日志 → Nginx 错误日志 |
| 简历一直等待解析 | `systemctl status ai-resume-worker` → Worker 日志 → `/api/v1/tasks/{id}` |
| JD 分析失败 | `LLM_BASE_URL/API_KEY/MODEL`、模型接口兼容性、API 日志 |
| 扫描 PDF 解析失败 | 视觉模型是否支持图片、`RESUME_VISION_*`、PDF 清晰度和页数 |
| 无法连接 MySQL | 网络白名单、账号权限、`MYSQL_SSL`/CA、API 日志 |
| 磁盘增长过快 | `/var/lib/ai-resume-screening/storage` 容量、岗位删除策略、备份策略 |

常用命令：

```bash
sudo systemctl restart ai-resume-api ai-resume-worker
sudo journalctl -u ai-resume-worker -n 200 --no-pager
sudo nginx -t
df -h /var/lib/ai-resume-screening/storage
```

## 15. 备份与安全底线

- 每日备份 MySQL，并定期验证恢复流程；数据库备份必须加密并控制访问。
- 备份本地存储目录，否则数据库中的 `storage_key` 无法恢复原始 PDF。
- 只对外开放 80/443；MySQL 和 Uvicorn 端口仅允许内网或本机访问。
- 定期更新系统、Python 依赖和 Node 构建环境；服务账号不应拥有 sudo 权限。
- 启用 HTTPS 后再对外提供登录和简历上传服务。
- 部署前复核 [安全与权限文档](05-安全合规与权限.md) 的未完成项，尤其是多账户数据隔离、文件安全、个人信息加密和审计。
