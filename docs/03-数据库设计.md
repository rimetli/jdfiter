# 03 数据库设计

## 1. 通用约定

- MySQL 8.0，存储引擎使用InnoDB，字符集使用`utf8mb4`。
- 主键默认使用`bigint unsigned`；单体MVP可自增，未来分布式部署可切换雪花ID。
- 时间使用`datetime(3)`并以UTC写入，统一`created_at/updated_at`；API按用户时区展示。
- 所有业务表带`organization_id`实现租户隔离。
- `json`只保存结构不稳定内容；可查询、关联和约束的数据使用普通列。
- 金额和分数使用`decimal`，禁止使用浮点数。
- 状态字段使用`varchar`，不使用MySQL `enum`，便于版本迁移。
- 敏感字段加密；删除默认软删除，合规删除走独立任务。

## 2. 核心关系

```text
organization ─ users
      └─ jobs ─ requirement_versions ─ requirement_items
           └─ applications ─ evaluations ─ score_details ─ evidences
candidate ─ resumes ─ parse_versions
      └──── applications
evaluation ─ human_decisions / interview_feedback
```

## 3. 表定义

### organizations / users

- `organizations(id, name, status, created_at)`
- `users(id, organization_id, email_ciphertext, display_name, role, status, created_at)`
- 约束：`unique(organization_id, email_hash)`

### job_positions

- `id, organization_id, name, department, jd_content`
- `status`：DRAFT/REVIEW/ACTIVE/ARCHIVED
- `active_requirement_version_id`
- `created_by, created_at, updated_at, archived_at`

### job_requirement_versions

- `id, job_id, version_no, summary, rubric_version`
- `weight_config json, status, created_by, published_at`
- 约束：`unique(job_id, version_no)`；已发布版本不可更新

### requirement_items

- `id, requirement_version_id, dimension_code`
- `name, description, requirement_type`
- `max_score decimal(5,2), is_gate tinyint(1), acceptable_alternatives json`
- `evidence_rule, sort_order`
- `requirement_type`：MUST_HAVE/NICE_HAVE/RISK

### candidates

- `id, organization_id`
- `name_ciphertext, name_hash, email_ciphertext, email_hash`
- `phone_ciphertext, phone_hash, source`
- `consent_status, retention_until, deleted_at`

### resume_files

- `id, candidate_id, storage_key, original_filename`
- `mime_type, size_bytes, sha256, malware_status`
- `uploaded_by, created_at, deleted_at`
- 对象存储路径不能直接作为公开URL。

### resume_parse_versions

- `id, resume_file_id, version_no, status`
- `parser_version, ocr_used, normalized_text_storage_key`
- `profile_json json, validation_errors json`
- `started_at, completed_at, created_at`

完整文本宜单独加密存储，数据库只保留受控引用。

### job_applications

- `id, job_id, candidate_id, resume_file_id`
- `stage, source, created_at, updated_at`
- 约束：同一候选人可申请多个岗位。

### processing_tasks

- `id, organization_id, task_type, entity_type, entity_id`
- `status, progress, attempt_count, error_code, error_message_safe`
- `priority, available_at, locked_by, locked_at`
- `input_hash, started_at, completed_at, created_at`

Worker使用短事务和`SELECT ... FOR UPDATE SKIP LOCKED`抢占任务，提交后再执行耗时操作。超出锁定时限的任务可被回收；任务处理必须幂等。

### candidate_evaluations

- `id, application_id, parse_version_id, requirement_version_id`
- `status, total_score decimal(5,2), level, gate_result`
- `summary_json json, confidence decimal(4,3)`
- `rubric_version, prompt_version, model_provider, model_name`
- `supersedes_evaluation_id, created_at, completed_at`

必须通过唯一输入快照生成；重评创建新行。

### evaluation_score_details

- `id, evaluation_id, dimension_code, item_code`
- `status`：MET/PARTIAL/UNKNOWN/NOT_MET
- `score, max_score, confidence, reason`
- `calculation_json`

### evaluation_evidences

- `id, score_detail_id, parse_version_id`
- `page_no, block_id, quote_text, bbox_json`
- `evidence_type`：DIRECT/INFERRED
- MVP评分只允许DIRECT证据；推断只能进入待确认项。

### human_decisions

- `id, evaluation_id, decision, reason_code, comment`
- `decided_by, created_at`
- 不覆盖AI结论。

### interview_feedback

- `id, application_id, round_name, result`
- `dimension_feedback json, comment, interviewer_id, created_at`

### model_call_logs / audit_logs

- 模型日志：调用阶段、模型、Prompt版本、Token、成本、耗时、结果状态；禁止保存完整明文简历。
- 审计日志：操作者、动作、实体、时间、IP摘要、变更前后摘要。

## 4. 索引

- 所有表索引`organization_id`。
- `job_positions(organization_id, status, updated_at)`
- `job_applications(job_id, stage, created_at)`
- `candidate_evaluations(application_id, created_at)`
- `processing_tasks(status, created_at)`
- `processing_tasks(status, available_at, priority)`
- 邮箱/电话只对不可逆哈希建索引。
- MySQL 8支持降序索引，但MVP按普通联合索引即可；排序方向由查询指定。
- 外键用于核心归属关系；高频日志表可根据规模评估是否保留物理外键。

## 5. 数据保留

- 默认保留期限由企业配置，例如12个月。
- 到期前提示管理员；到期后删除文件、解析文本和个人字段。
- 审计日志按合规策略保留，但不得保留可恢复的简历正文。

## 6. MySQL实现注意事项

- 所有表显式设置`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`。
- `organization_id`必须出现在业务唯一索引中，避免不同租户之间误冲突。
- JSON中需要频繁筛选的字段应提升为普通列，或通过生成列建立索引。
- ID、时间和状态由服务端生成，数据库迁移统一使用Alembic管理。
- 人才语义检索不属于MVP；需要时优先增加独立向量服务，不把向量直接塞入普通MySQL字段。
