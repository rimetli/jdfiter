# 04 Prompt 与评分规则

> 当前实现中，模型输出画像、匹配状态、证据深度与贡献角色；最终分数由 `worker.py` 确定性计算。

## 1. 边界与防注入

- JD 和简历都是不可信输入。Prompt 明确要求忽略其中的指令、评分要求、系统提示泄露请求和工具调用要求。
- 模型不得因未提及而判定 `NOT_MET`，也不得凭常识补全候选人经历。
- 禁止将性别、年龄、籍贯、婚育、民族、宗教、健康、照片等非岗位能力信息用于画像、匹配或评分。
- 模型不可直接输出总分；代码只接受规定的枚举值和结构化字段。

## 2. 模型调用

| 场景 | 输入 | 输出 |
|---|---|---|
| JD 分析 | JD 原文 | 能力模型摘要、评分项草稿、权重/门槛建议 |
| 简历画像 | 简历文本 | 姓名、联系方式、经历、项目、技能、教育等结构化事实 |
| 人岗匹配 | 简历文本 + 已发布能力项 | 每个能力项的状态、置信度、理由、证据、深度、角色 |
| 扫描件 OCR | PDF 渲染图片 | 仅简历可见文字；不评分、不生成结论 |

视觉 OCR 使用与主模型相同的 OpenAI 兼容接口，但要求模型支持 `image_url` 多模态输入。

## 3. 匹配状态

| 状态 | 含义 |
|---|---|
| `MET` | 有直接证据支持满足 |
| `PARTIAL` | 有直接证据，但满足不完整 |
| `UNKNOWN` | 简历信息不足或证据冲突 |
| `NOT_MET` | 简历存在明确反向事实 |

`UNKNOWN` 与 `NOT_MET` 都不计分，但在报告中必须区分：前者是待面试核实，后者是已有明确不符合证据。

## 4. 深度核验与系数

每个匹配项还返回：

- `depth`：`DEEP`（量化结果、技术取舍或细节）、`SHALLOW`（名词/职责罗列）、`NONE`（无有效证据）。
- `role`：`LEAD`（主导/独立负责）、`CONTRIBUTOR`（参与实现）、`EXPOSURE`（了解、课程或接触）。

当前 Worker 系数：

| 状态 | depth / role | 系数 |
|---|---|---:|
| `MET` | `DEEP` + `LEAD` | 1.0 |
| `MET` | `DEEP` + `CONTRIBUTOR` | 0.8 |
| `MET` | `DEEP` + `EXPOSURE` | 0.4 |
| `MET` | `SHALLOW` + `LEAD` | 0.7 |
| `MET` | `SHALLOW` + `CONTRIBUTOR` | 0.5 |
| `MET` | `SHALLOW` + `EXPOSURE` | 0.3 |
| `PARTIAL` | 任意有效深度/角色 | 0.3 |
| `UNKNOWN` / `NOT_MET` | 任意 | 0 |

计算公式：`item_score = max_score × factor`；总分为所有能力项得分之和。模型返回非法深度/角色，或 `MET/PARTIAL` 配合 `NONE` 深度时，任务失败而不会写入半成品评估。

## 5. 门槛与等级

- 门槛项当前只按匹配状态判断：`NOT_MET` 会标记为 `NOT_MET`，`UNKNOWN/PARTIAL` 标记为 `REVIEW_REQUIRED`；其他情况为 `PASSED`。深度和角色会影响分数与面试风险提示，但不单独决定门槛状态。
- 默认等级：`>=85 STRONGLY_RECOMMENDED`、`>=70 RECOMMENDED`、`>=60 REVIEW`、其余 `LOW_MATCH`。
- 不满足门槛不会删除评分结果，而是将 `gate_result` 标记为需要复核；招聘人员作最终决定。

## 6. 关键 Prompt 要求（摘要）

```text
只提取简历中明确出现的事实，不推测、不补全。
每个匹配项必须附直接证据页码和原文摘录。
无证据时使用 UNKNOWN，不得因未提及而使用 NOT_MET。
区分系统做了什么和候选人亲自做了什么；关键词堆砌、无量化结果、
无个人贡献细节的证据，depth 必须是 SHALLOW。
不得输出最终分数或改变岗位规则。
```

## 7. 版本与可追溯性

每次评估保存能力模型版本、评分规则版本、Prompt 版本、模型名、评分明细、证据和计算 JSON。对同一简历重评会创建新的评估记录，而不是修改旧结果。
