# 05 安全、隐私与权限

> 本文说明现状和上线前要求，不构成法律意见。系统会处理联系方式、教育和工作经历，正式投入招聘前应由企业法务与安全负责人审查。

## 1. 已实现的基础保护

- 密码仅保存 scrypt 派生哈希；登录返回 24 小时 HMAC 签名 Bearer Token。
- 只有管理员可以列出和创建普通账户；普通账户不能自行注册。
- 岗位创建、列表、详情、修改、删除及 JD 分析会读取当前用户：普通用户仅可访问自己创建的岗位，管理员可访问全部岗位。
- 上传仅接受带 `%PDF-` 文件头的 PDF，限制为 20 MB；解析与模型任务脱离 API 请求在 Worker 中运行。
- Prompt 要求将 JD、简历视作不可信内容，不将受保护属性用于评分。
- Token、模型密钥、MySQL 密码通过 `backend/.env` 提供，不应提交 Git 或打印到日志。

## 2. 当前限制（不可视为已满足生产合规）

- 首次安装的 `/setup/bootstrap`、`/setup/admin` 必须保持匿名可用；生产部署应只在受控网络中执行初始化，完成后限制这两个入口。
- 文件为本地磁盘存储，未使用私有对象存储、短时签名下载链接或恶意软件扫描。
- `*_ciphertext` 个人字段目前尚未做应用层加密；日志脱敏、审计日志、导出控制和保留期限任务也未完整实现。
- 当前令牌无刷新、撤销、MFA、SSO 和密码重置机制。
- OCR/LLM 会把完成当前任务所需的简历内容发送给配置的模型供应商；使用前需确认该供应商的数据保留、训练与跨境传输政策。

## 3. 生产上线前必做项

1. 对岗位、候选人、简历、任务、评估、能力模型接口持续执行管理员越权与普通用户越权回归测试。
2. `APP_SECRET` 使用高熵随机值，HTTPS 终止于反向代理；令牌加刷新、失效和登出策略。
3. 将文件转入受控私有对象存储，加入病毒扫描、下载授权和访问审计；限制 PDF 解析 CPU、内存与超时。
4. 评估个人信息字段加密、密钥托管、日志脱敏、备份加密和恢复演练。
5. 实现候选人删除/保留策略，覆盖文件、解析文本、画像、评估及备份处理。
6. 为模型输出增加 JSON Schema/业务校验、超时/重试限制，并定期做 Prompt 注入测试。
7. 明确人工最终决策责任；不得基于受保护属性自动淘汰候选人。

## 4. 操作要求

- 不把 `.env`、真实简历、数据库备份和模型密钥放入代码仓库或工单附件。
- 管理员创建普通用户后，应通过安全渠道传递初始密码，并要求首次登录后更换密码（该改密功能当前尚未开发）。
- 生产模型优先选用可关闭训练/保留的企业服务，并保留供应商配置、用途和数据处理记录。
