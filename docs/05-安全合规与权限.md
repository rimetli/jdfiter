# 05 安全合规与权限

## 1. 基线

系统处理个人联系方式、教育和就业经历等敏感招聘数据。上线前应由企业法务和安全负责人结合实际运营地区完成审查。本文件是产品和工程基线，不替代法律意见。

## 2. 数据最小化

- 只收集筛选所需信息。
- 默认盲筛；受保护或无关属性不得进入Prompt和评分。
- 原始文件、规范化文本和日志分开存储。
- 模型调用仅发送完成任务所需片段。
- 禁止用候选人数据训练第三方模型，除非获得明确授权。

## 3. 访问控制

- RBAC＋organization_id强制租户隔离。
- 岗位级授权给面试官。
- 原文件通过短时签名URL访问。
- 下载、导出、删除、查看联系方式均写审计日志。
- 管理员启用MFA；生产环境优先企业SSO。

## 4. 加密与密钥

- 传输使用TLS。
- 对象存储和数据库磁盘加密。
- 姓名、邮箱、电话等字段应用层加密；检索使用不可逆哈希。
- 密钥存放于密钥管理服务，禁止写入代码、镜像或日志。
- 定期轮换密钥和模型API凭据。

## 5. 文件安全

- 同时校验扩展名、MIME和文件头。
- 上传后先隔离并进行恶意软件检测。
- PDF解析在受限Worker中执行，限制CPU、内存和处理时间。
- 拒绝加密、损坏或超限文件，并给出安全错误信息。

## 6. LLM安全

- JD和简历标记为不可信内容。
- 系统指令与资料使用独立消息和明确分隔。
- 只接受JSON Schema输出，不执行模型返回的代码、URL或工具调用。
- Prompt注入测试纳入发布门禁。
- 选择提供“不用于训练、可配置零保留”的企业模型服务；记录供应商配置。
- 模型失败时进入失败状态，不降级成无证据的自由文本评分。

## 7. 公平性与人工监督

- 系统不得根据性别、年龄、民族、籍贯、婚育、宗教、残障等属性评分。
- 学历若非岗位真实必要条件，不设置硬门槛。
- 总分不得成为自动淘汰的唯一依据。
- UI明确显示“AI辅助建议”，人工结论独立保存。
- 定期抽样检查不同群体的推荐率和错误率；发现异常时暂停相关规则。

## 8. 保留、删除与事件响应

- 企业配置保留期限，默认建议12个月。
- 支持查询、更正、导出和删除候选人数据。
- 删除覆盖对象文件、解析文本、结构化画像和可识别字段，并留下不可识别审计证明。
- 建立泄露响应流程：发现、隔离、评估、通知、修复、复盘。
- 备份同样遵守加密和到期删除策略。

## 9. 上线安全清单

- 租户越权与岗位越权测试通过
- 文件上传和PDF解析安全测试通过
- 日志中无简历正文和密钥
- 数据删除演练通过
- 模型供应商数据策略确认
- Prompt注入与输出Schema测试通过
- 管理员MFA、备份恢复和告警可用
