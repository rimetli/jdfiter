# 06 本地运行、测试与上线检查

## 1. 前置条件

- Python 3.12（或与项目虚拟环境一致的版本）、Node.js 20+、MySQL 8。
- 已配置 `backend/.env` 的 MySQL、模型、视觉 OCR、存储和认证密钥。
- 视觉 OCR 功能要求模型支持图片输入；仅文本 PDF 不依赖该能力。

## 2. 本地启动

在项目根目录分别开启三个终端：

```bash
cd backend
source .venv/bin/activate
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
cd backend
source .venv/bin/activate
python -m app.worker
```

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:5173/`。管理员可在登录后创建普通账户。

### 首次初始化说明

后端提供了无需登录的组织初始化接口，但当前前端未初始化时会跳转到登录页，无法直接打开旧的初始化面板。因此空数据库首次部署时，先执行一次：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/setup/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"organization_name":"你的公司或团队"}'
```

然后访问 `/login` 创建管理员账号并登录。这是当前 UI 与初始化流程之间的已知缺口；后续应将组织初始化并入登录页。

## 3. 构建与自动检查

```bash
cd backend
source .venv/bin/activate
ruff check app migrations
pytest

cd ../frontend
npm run build
```

建议在提交或部署前执行以上命令。前端构建产生的 `dist`、`node_modules`、`*.tsbuildinfo` 不应提交版本库。

## 4. 最小验收路径

1. 健康检查：访问 `/api/v1/health` 和 `/api/v1/health/database`。
2. 首次初始化：通过 `setup/bootstrap` 创建组织后，在登录页创建管理员；管理员登录后创建一个普通账户并验证可登录。
3. 岗位：普通用户创建岗位、AI 分析 JD、人工修改能力模型并发布。
4. 上传：上传文本 PDF；再上传扫描 PDF 验证视觉 OCR；确认电话优先/无电话邮箱去重提示。
5. 任务：确认 Worker 将解析任务置为 `COMPLETED`；停止 Worker 时应能从任务接口看到 `PENDING/PROCESSING` 状态，而非前端假完成。
6. 批量分析：选择多份已解析简历，提交批量分析；查看总分、状态、证据、深度/角色和人工结论。
7. 删除：删除测试岗位，确认只清理该岗位独占的数据，不误删其他岗位仍引用的候选人。
8. 权限：普通用户不能读取其他用户的岗位、候选人、任务、评估或能力模型；管理员可查看同组织全部数据。
9. 可靠性：停止 Worker 并等待超过 `TASK_LEASE_SECONDS`，确认任务被回收；确认失败任务在达到 `TASK_MAX_ATTEMPTS` 前按退避自动重试，超过上限后显示 `FAILED`。

## 5. 常见问题

| 现象 | 优先检查 |
|---|---|
| 页面点击后无反应 | 浏览器控制台、API 是否运行、前端 `VITE_API_BASE_URL` |
| JD 分析失败 | `LLM_BASE_URL/API_KEY/MODEL`、模型是否兼容 chat completions、后端日志 |
| 简历一直等待解析 | Worker 是否运行、任务接口错误信息、数据库连接 |
| 扫描 PDF 失败 | `RESUME_VISION_ENABLED`、视觉模型是否支持图片、页数/DPI、PDF 清晰度 |
| 上传提示重复 | 从 PDF 提取出的电话相同；无电话时邮箱相同 |
| 数据库迁移失败 | 当前库版本、数据库账号 DDL 权限、Alembic 日志；不要手工跳过迁移版本 |

## 6. 生产部署检查

- API、Worker、MySQL 使用独立进程/容器并通过进程守护自动重启。
- 前端构建静态文件由 Nginx 等 Web 服务器托管，反向代理 `/api` 到 API 服务，并强制 HTTPS。
- `backend/.env` 由部署平台密钥管理提供，禁止写入镜像；`APP_SECRET` 使用随机值。
- 将本地文件存储替换为受控持久卷或私有对象存储，并制定备份、恢复、清理策略。
- 完成文档 05 的全链路鉴权、加密、文件安全、日志与删除改造后，再开放给多用户生产使用。
