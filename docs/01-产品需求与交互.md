# 01 产品需求与交互

## 1. 产品定义

AI招聘辅助决策系统，不自动做出录用或淘汰决定。目标用户为HR、技术面试官和系统管理员。

## 2. MVP范围

### 包含

- 岗位创建、编辑、归档
- JD文本输入或文件上传
- AI生成能力模型，人工确认后发布
- 单份/批量PDF简历上传
- 文本解析及扫描件OCR
- 候选人画像、六维评分、证据引用
- 列表筛选排序、详情查看、候选人横向对比
- 人工推荐/待定/淘汰及原因记录
- 失败重试、版本记录、操作审计

### 暂不包含

- 自动淘汰、自动发信
- AI视频面试
- 自动学习并修改评分权重
- 人才知识图谱
- 多模型动态路由
- 独立向量数据库

## 3. 角色权限

| 功能 | 管理员 | HR | 面试官 |
|---|---:|---:|---:|
| 用户与权限 | 是 | 否 | 否 |
| 岗位管理 | 是 | 是 | 只读 |
| 发布能力模型 | 是 | 是 | 可评论 |
| 上传/删除简历 | 是 | 是 | 否 |
| 查看候选人 | 是 | 是 | 被授权岗位 |
| 人工决策 | 是 | 是 | 提交建议 |
| 面试反馈 | 是 | 是 | 是 |
| 查看审计日志 | 是 | 否 | 否 |

## 4. 页面与交互

### 4.1 岗位列表

显示岗位名称、部门、状态、能力模型版本、候选人数、完成/失败任务数、更新时间。支持搜索、状态筛选、创建、复制和归档。

### 4.2 创建岗位

输入岗位名称、部门、JD、默认评分模板。保存后触发JD分析。

### 4.3 JD分析确认

分组展示必备项、加分项、业务经验、工作年限和风险项。允许：

- 修改名称、说明、分值和证据要求
- 设置替代技能
- 设置硬门槛
- 保证权重合计100
- 预览规则并发布版本

发布后不可直接修改；修改生成新版本。历史候选人仍关联旧版本，可人工选择是否重评。

### 4.4 候选人列表

支持批量上传，展示姓名（盲筛模式下为编号）、解析状态、总分、推荐等级、必备项满足情况、风险、人工结论。支持按分数、维度、标签、状态筛选和排序。

### 4.5 候选人详情

左侧展示PDF和高亮证据，右侧展示：

- 总分、推荐等级、人工结论
- 六维评分和置信度
- 满足/部分满足/未知/不满足项
- 优势、风险、待确认信息
- 针对性面试问题
- 模型、Prompt、规则版本

点击评分项时定位至简历页码和原文。用户可纠正抽取事实或提交人工评分，修改必须填写原因且不覆盖AI原始结果。

### 4.6 横向对比

一次比较2–5人，按必备条件和评分维度形成矩阵。不得仅用总分决定排序，优先展示硬门槛和未知项。

### 4.7 任务中心

显示上传、解析、OCR、评估和报告任务的进度、耗时、错误原因和重试按钮。

## 5. 状态模型

岗位：`DRAFT → REVIEW → ACTIVE → ARCHIVED`

简历任务：

```text
UPLOADED → PARSING → EXTRACTING → EVALUATING → COMPLETED
                       └──────────────→ FAILED
```

人工结论：`UNDECIDED / INTERVIEW / HOLD / REJECT`

## 6. 关键业务规则

- 能力模型未发布时不可评分。
- 文件SHA-256相同且候选人相同则提示重复。
- 证据不足使用`UNKNOWN`，不得自动判为`NOT_MET`。
- 硬门槛不满足时总分照常计算，但推荐等级最高为“待定”，由人工确认。
- 重新解析、重评均创建新记录，不覆盖历史数据。
- 同一岗位默认按同一规则版本评估。

## 7. 非功能要求

- 文件：PDF，单份≤20MB；MVP每批≤50份。
- 性能：普通文本PDF P95在90秒内完成；扫描件P95在180秒内完成。
- 可用性：核心操作月可用性≥99.5%。
- 可访问性：关键流程支持键盘操作，状态不只用颜色表达。
- 成本：记录每份简历的模型Token、OCR和总成本。
